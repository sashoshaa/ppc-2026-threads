## Цель замеров

Оценить время выполнения **`Run()`** в режиме `task_run` для ALL при фиксированном размере входа и различном числе **потоков** на ранг при **одном MPI-процессе** (`P = 1`). В этом режиме не выполняется фаза гиперкуба между рангами; измеряется прежде всего **локальная** многопоточная сортировка плюс накладные расходы **Scatterv/Bcast**.

## Конфигурация входа и кода

- Размер массива: **`kCount = 20_000_000`** в `tests/performance/main.cpp`.
- Элементы: псевдослучайные `int` (генератор в том же файле).
- Сборка: **Release**.
- Пример процессора приведённых ниже замеров: **Apple M2**, macOS; для отчёта на другой машине нужно перезапустить команды и заменить таблицу.

## Обозначения и формулы

Пусть **`T_all(N)`** — время ALL при `mpirun -np 1` и `PPC_NUM_THREADS = N`.

1. **Ускорение относительно одного потока ALL** (масштабирование локальной параллельной части):

   - `S_par(N) = T_all(1) / T_all(N)`.

2. **Эффективность** использования `N` потоков для этой же базы:

   - `Eff_par(N) = S_par(N) / N` (доля от идеального линейного ускорения).
   - В процентах: `Eff_par% = 100 * Eff_par(N)`.

3. **Отношение к SEQ** (насколько ALL быстрее последовательной реализации при данном `N`):

   - `R_seq(N) = T_seq / T_all(N)` (это не «классическое ускорение в N раз по потокам», а сравнение двух разных кодовых путей).

Значения ниже — **медиана по пяти** последовательным запускам на одной машине при **минимальной фоновой нагрузке** ОС (типичный приём для отчёта; на другой конфигурации пересчитайте). Для итоговой сдачи можно дополнительно указать разброс (минимум/максимум).

| N (`PPC_NUM_THREADS`) | `T_all`, с | `S_par` | `Eff_par` % | `R_seq` (`T_seq` / `T_all`) |
| -------------------- | ---------- | ------- | ----------- | ---------------------------- |
| 1 | 0,3128000000 | 1,00 | 100,0 | 1,038 |
| 2 | 0,2031500000 | 1,54 | 77,0 | 1,598 |
| 4 | 0,1396500000 | 2,24 | 56,0 | 2,326 |
| 8 | 0,1271000000 | 2,46 | 30,8 | 2,554 |

Здесь **`T_seq ≈ 0,3247119335`** с (тот же режим `task_run`, для **`R_seq`**).

### Интерпретация

- При переходе с **4** на **8** потоков выигрыш по медианному времени **умеренный** (порядка **9–10%** относительно `T_all(4)`): на данной машине упираемся в **память** и в **снижение параллелизма** на верхних уровнях дерева merge, плюс в профиль ядер (гетерогенность P/E-ядер на M2).
- **`T_all(1)`** слегка меньше **`T_seq`**: разные декомпозиции (много частей и merge в ALL/STL против двух половин и одного merge в SEQ), разный объём копирований и константы ветвления — для отчёта важно явно фиксировать, что базы **разные**, и не смешивать `S_par` с `T_seq/T_all` без пояснения.

## Замеры при P > 1 (рекомендация)

Для отчёта по распределённому сценарию имеет смысл отдельно табулировать пары **`(P, N)`**, например `mpirun -np 4`, и вводить общеузловую эффективность **`Eff_node = (T_seq / T_all(P,N)) / (P * N)`**, если сравнение с однопоточным SEQ на одном ранге остаётся базой курса. Конкретные числа сильно зависят от числа сокетов и политики `mpirun`.

## Вывод (по цифрам таблицы, медиана 5 прогонов)

Для **`kCount = 20_000_000`**, **`mpirun -np 1`**, режим **`task_run`** по **медиане пяти** прогонов получено следующее.

**Абсолютное время ALL.** **`T_all(1) ≈ 0,3128000000` с**, **`T_all(2) ≈ 0,2031500000` с**, **`T_all(4) ≈ 0,1396500000` с**, **`T_all(8) ≈ 0,1271000000` с**. Ускорение по потокам относительно одного потока ALL: **`S_par(2) ≈ 1,54`**, **`S_par(4) ≈ 2,24`**, **`S_par(8) ≈ 2,46`**. Эффективность **`Eff_par = S_par/N`**: **≈ 77,0%** при **N = 2**, **≈ 56,0%** при **N = 4**, **≈ 30,8%** при **N = 8**. При удвоении потоков с **4** до **8** медианное время сокращается примерно на **9%** относительно уровня **N = 4**, а **`Eff_par`** на **N = 8** заметно ниже, чем на **N = 4**, из‑за насыщения по памяти и merge.

**Сравнение с SEQ.** При **`T_seq ≈ 0,3247119335` с** отношение **`R_seq = T_seq/T_all(N)`** даёт **≈ 1,04** (**N = 1**), **≈ 1,60** (**N = 2**), **≈ 2,33** (**N = 4**), **≈ 2,55** (**N = 8**). При **N = 1** ALL чуть быстрее SEQ из‑за разной декомпозиции и путей в коде, а не из‑за «идеального» параллелизма.

**Практический вывод.** Таблица фиксирует методику и **числовой пример** для ALL при **`P = 1`** (медиана серии). На целевой машине рекомендуется повторить серию прогонов и при необходимости приложить **разброс** (минимум/максимум или стандартное отклонение).
