## Введение

Цель данного отчета — сравнить производительность всех реализованных версий
алгоритма поразрядной сортировки с простым слиянием:

- `seq` (последовательная);
- `omp` (OpenMP);
- `tbb` (oneTBB);
- `stl` (`std::thread`);
- `all` (MPI + потоки).

## Постановка задачи

Для единой входной задачи (сортировка массива целых чисел) требуется оценить:

1. абсолютные времена выполнения в режиме `task_run`;
2. ускорение относительно последовательной версии;
3. эффективность использования параллелизма.

## Методика измерений

### Тестовая конфигурация

- Вход: массив псевдослучайных `int` размера 20 млн элементов.
- Источник теста: `tests/performance/main.cpp`.
- Режим: `task_run` (измеряется только `Run()`).
- Для потоковых версий задается `PPC_NUM_THREADS = N`.
- Для ALL задаются `P` (MPI-ранги) и `N` (потоки на ранг).

### Формулы

- `S = T_seq / T_par` — ускорение.
- Для OMP/TBB/STL: `Eff = S / N`.
- Для ALL:
  - при `P = 1`: `Eff = S / N`;
  - при `P > 1`: общеузловая эффективность `Eff = S / (P * N)`.

## Анализ результатов

1. **Лидер среди потоковых версий на данной машине — TBB.**
   На всех N он показывает немного большее ускорение, чем OMP и STL.
2. **OMP и STL дают близкие результаты.**
   Разница невелика, особенно на N = 2 и N = 4.
3. **С ростом N эффективность падает у всех потоковых реализаций.**
   Основные причины: память, синхронизация и снижение параллелизма на поздних
   уровнях дерева merge.
4. **ALL при P = 1 близок к STL, но чуть слабее.**
   Добавляются накладные расходы MPI-обвязки (`Scatterv`, `Bcast`).
5. **ALL при P > 1 на одном узле не масштабируется линейно.**
   Конкурируют процессы и потоки за одни и те же ядра и память, добавляются
   межпроцессные обмены (`Sendrecv`) в фазе гиперкуба.

## Практические рекомендации

- Для одной машины с общим адресным пространством в первую очередь выбирать
  `tbb` или `omp`.
- Использовать `N = 4` как рабочий компромисс ускорения/эффективности.
- ALL применять, когда действительно нужен MPI-сценарий (например, несколько
  узлов), иначе накладные расходы могут нивелировать выигрыш.

## Вывод

Все реализации корректны и ускоряют задачу относительно SEQ. На рассматриваемой
платформе лучшую производительность среди потоковых версий показывает TBB,
а гибридный ALL полезен как расширение к распределенной модели вычислений.
