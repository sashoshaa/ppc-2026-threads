## Введение

STL-версия реализует многопоточность средствами стандартного C++ (`std::thread`)
без использования OpenMP и TBB рантаймов.

## Постановка задачи

Требуется получить переносимую реализацию radix+merge, где параллелизм задается
явным запуском потоков и ручным разбиением диапазонов индексов.

## Описание реализации

Реализация: `stl/src/ops_stl.cpp`, класс `SosninaATestTaskSTL`.

### Принцип работы

1. Определяется число потоков `num_threads = GetNumThreads()`.
2. Вычисляется `num_parts` с учетом порогов размера.
3. Массив делится на `num_parts` подмассивов.
4. Подмассивы сортируются параллельно через `ParallelForRange`.
5. Слияние выполняется по уровням дерева; пары на уровне также
   распараллеливаются через `ParallelForRange`.
6. Итог проверяется через `std::ranges::is_sorted(data)`.

### Псевдокод

```text
разбить data на parts

ParallelForRange(0, num_parts, num_threads):
    LSD-sort(parts[i])

current <- parts
while |current| > 1:
    pair_count <- |current| / 2
    ParallelForRange(0, pair_count, num_threads):
        next[idx] <- merge(current[2*idx], current[2*idx+1])
    перенос хвоста при нечётном количестве частей
    current <- next
data <- current[0]
```

## Оценка сложности

- Теоретически: линейные radix-проходы и merge.
- Практически: эффективность зависит от зернистости частей и стоимости merge.

## Экспериментальные результаты

### Аппаратное и программное окружение

- Процессор: Apple M2 (8 CPU ядер).
- Операционная система: macOS.
- Тип сборки: Release.

### Корректность

Функциональные тесты (`tests/functional/main.cpp`) проходят успешно.
Внутри `RunImpl()` выполняется контроль `std::ranges::is_sorted(data)`.

### Производительность (STL)

Метрики приведены относительно SEQ: `S = T_seq / T_stl`, `Eff = S / N`.

| Число потоков N | Ускорение S | Эффективность Eff |
| --------------- | ----------- | ----------------- |
| 2               | 1,86        | 93%               |
| 4               | 2,55        | 63,8%             |
| 8               | 2,92        | 36,5%             |

## Анализ

- Версия на `std::thread` дает стабильное ускорение на `N = 2..4`.
- На `N = 8` эффективность падает по тем же причинам, что и в других
  многопоточных версиях: merge и память.
